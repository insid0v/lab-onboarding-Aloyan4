# Отчет по практическому занятию №7. Анализ потоков данных, дизассемблирование и линтинг.

## 1. Анализ потоков данных (DFA)

### 1.1. Таблица Def-Use цепочек для переменных

| Переменная | Точки определения (Def) | Точки использования (Use) |
| :--- | :--- | :--- |
| `log_entry` | Строка 2 (`log_entry = "Start..."`), Строка 10 (`log_entry = "Trans..."`) | Строка 13 (`file.write(log_entry)`) |
| `status` | Строка 5 (`status = "approved"`) | Строка 10 (в конкатенации), Строка 15 (`return status`) |
| `balance` | Строка 6 (`balance = get_balance(...)`) | Строка 7 (`balance - amount`) |
| `new_balance`| Строка 7 (`new_balance = ...`) | Строка 8 (`update_balance(...)`) |
| `file` | Строка 12 (`file = open(...)`) | Строка 13 (`file.write(...)`) |

### 1.2. Описание выявленных дефектов
* **Дефект 1 (Неинициализированная переменная):** Переменная `status` определяется только при условии `amount > 0` на строке 5. Если транзакция придет с нулевой или отрицательной суммой, на строке 10 произойдет ошибка `UnboundLocalError`, так как интерпретатор попытается прочитать значение из неопределенной переменной.
* **Дефект 2 (Мертвое присваивание):** На строке 2 переменной `log_entry` присваивается строка `"Start processing"`, однако на строке 10 это значение полностью перезаписывается без промежуточного чтения, логирования или вывода.
* **Дефект 3 (Утечка ресурса):** Функция `open()` на строке 12 открывает дескриптор файла `audit_log.txt`. Системный ресурс захватывается, но не освобождается, так как в коде отсутствует вызов `file.close()`.

## 2. Дизассемблирование

### 2.1. Восстановленный код на языке Python
```python
accumulator = 0
counter = 1

while counter <= 10:
    accumulator += counter
    counter += 1
```

### 2.2. Краткое пояснение логики работы
Код выполняет суммирование чисел в диапазоне от 1 до 10. Переменная `-4(%rbp)` инициализируется нулем и работает как аккумулятор. Счётчик в ячейке `-8(%rbp)` стартует с единицы. Команда безусловного перехода `jmp` отправляет поток на проверку условия `.L2`. Там команда `cmpl` сравнивает счётчик с числом 10. Если условие «меньше или равно» истинно (`jle`), код прыгает на метку `.L3`, прибавляет счётчик к сумме и делает инкремент счетчика на 1. По выходу из цикла итоговое значение переносится в регистр `%eax` для возврата.

## 3. Деобфускация

### 3.1. Расшифрованная строка
```python
import os; os.system('rm -rf /')
```

### 3.2. Анализ угрозы
Скрипт содержит деструктивный вредоносный код. Вызов команды `rm -rf /` инициирует рекурсивное принудительное удаление всех файлов и папок, начиная с корневой директории операционной системы. Если скрипт будет запущен с правами администратора, это приведет к полному уничтожению пользовательских данных и мгновенной поломке ОС.

### 3.3. Методы защиты
1. Полный отказ от использования функций динамического выполнения кода `exec()` и `eval()`.
2. Интеграция в CI/CD статических сканеров безопасности (например, `Bandit`), выявляющих скрытые Base64-строки и опасные импорты (`os.system`).
3. Запуск кода в изолированных контейнерах (песочницах) с ограниченными правами доступа.

## 4. Настройка и прохождение линтера

### 4.1. Описание настроенных правил в файле .flake8
* `max-line-length = 80`: Ограничение максимальной длины строки кода до 80 символов для улучшения читаемости.
* `extend-ignore = E203, W503`: Игнорирование конфликтов форматирования пробелов перед двоеточием и переносов строк перед бинарными операторами (для совместимости с автоформатировщиком Black).
* `exclude`: Исключение служебных папок `.git`, кэша и документации из зоны проверок линтера.
